## Acceptance criteria

- **4.6, all 5 modes work:** `test_every_mode_is_served_and_echoed`; friends keeps only friend rows newest first, paginates 23 rows with 0 repeats, honours hides and snoozes; `recent` unchanged. **The mode survives a new browser:** `test_patch_remembers_the_mode_and_a_new_browser_gets_it`, and e2e `home-modes.spec.ts` (ar and en) picks Friends, opens a second browser context with empty storage and finds Friends pressed and the friend's post shown.
- **4.7, a push does not replace the session and makes no ads call:** `test_peek_keeps_the_session_and_its_next_page` asserts the stored session is byte-identical after the peek, the ads stub is called once (page 1 only), page 2 reads the session (`fallback: false`) with 0 repeats; `test_peek_without_a_session_creates_none`. Web: the pill calls `feedService.peek(mode, asOf)` and never `home()`. Live e2e: a `for_you` page 1, a peek, then page 2 with `fallback: false` and 0 overlap.
- **4.8, 404 unless served, identical body:** `test_identical_404_for_missing_invisible_and_not_served` (9 cases: missing id, a private `only_me` post with no token and with a forged `follow_pull` token, visible-but-not-served, another viewer's token, garbage, a token for a different item, a non-uuid, a non-post type) all give `{"code": "not_found", "message": "Not found.", "details": []}`. A served item gives 200; an expired token, a hide, an unfollow and a block after serving give 404; a banned group member gets 404 for the group post; an unknown-age viewer gets 404 for an unlisted public reel (E9). No private data of others (`test_no_private_data_of_others_in_the_body`). Sensitive topic masked (`test_a_sensitive_topic_is_masked`; web shows «لأنك مهتم بموضوع تتابعه» / "It's about a topic you follow"). Web `whyThisPost.spec.ts` covers en and ar with `dir="rtl"`.
- **4.9, organic order identical with ads on and off:** `test_organic_order_is_identical_with_ads_on_and_off` in all 5 modes across every page. Default config: `ads.slots == [4]`, one ad, at the same index as before (web spec "puts the one default ad after the fifth post, as before"; slot 4 also when the server sends none); a second ad only with `[4, 14]` in the config.
- **4.11:** `test_billing_status_excluded.py`: 8 non-active values (`suspended`, `unfunded`, `past_due`, `pending`, `closed`, `Active`, ` active`, empty) never serve; the active control serves; reactivation serves again; `ads.E001` still fires in production. Live dev: 3 advertisers, all `active`; 3 eligible creatives, 0 non-active among them.
